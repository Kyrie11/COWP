# V48.73 OC-IRRW 工程审计、算法归因与 V48.74 OC-SVBW 设计

## 0. Executive decision

- **工程判决：PASS。** V48.73 结果足够可靠，可以做算法归因；没有需要先修复并重跑的工程阻断。
- **科学判决：STOP。** V48.73 没有通过预注册的 dual-selectivity、non-floor physical consistency 和 full-source admission 条件。
- **Promotion 判决：** N73 current-state anchoring 与 O73 jerk-limited response 均不进入 Main。它们只能作为“外部 response-set 细化已出现边际收益递减”的负证据。
- **下一主假设：** 不再继续完善 acceleration-history/jerk response envelope，而检验已 actuator-projected 的 executable recovery 是否满足统一的 finite-time signed-viability barrier。
- **下一版本：** V48.74 `OC-SVBW`, Observation-Consistent Signed-Viability Barrier Witness。

## 2. 按 V48.73 预注册顺序判定

### 2.1 Certificate identity

N73、O73 与 M72 的 positive-certificate sign/set identity 通过。说明新因子保持严格正值，没有通过翻转 certificate sign 或改变 candidate availability 获得表面收益。

### 2.2 `N73 - M72`: current-state anchoring

current-state anchoring 在部分 cell 改善 teacher-feasible/teacher-infeasible 轴，但无法同时改善 safe-positive/harmful 轴。它没有形成跨 split、跨 Near/Contact 的 selective trust。

结论：

```text
N73_ANCHORED_HULL = STOP as a complete mechanism
```

不能做 anchor interpolation、response horizon 或 gain sweep。

### 2.3 `O73 - N73`: history-derived jerk response

jerk-limited response 在部分 cell 改善另一条 retention 轴，但会在其余 cell 逆转或丢失 N73 的弱信号。它没有提供可复现的增量 interaction effect。

结论：

```text
O73_JERK_RESPONSE = STOP
```

不能通过 jerk clipping、history length、support scaling 或 per-regime selection 挽救。

### 2.4 `O73 - M72`: complete temporal reachability

完整 O73 相对 M72 的 ordering 变化主要处于 `1e-4` 到低 `1e-3` 量级；探索性 paired scene-cluster bootstrap 区间跨零。即使某些 sign-count 条件表面满足，也不构成 CCF-A 级、可复现的机制效应。

更关键的是，八个注册 cell 中没有一个同时满足：

```text
safe-positive retention > harmful retention
AND
teacher-feasible retention > teacher-infeasible retention
```

因此核心 dual-selectivity gate 为 0/8，直接否决 promotion。

### 2.5 Non-floor 与 full-source

排除 exact-0.5 structural-floor teacher-feasible rows 后，O73 没有形成稳定正的 physical ordering；相对 accepted reference/native source 的完整增益也未达到注册的 8/8 正向、6/8 `>= +0.01` 和 safe-positive admission 条件。

最终判决：

```text
V48.73 OC-IRRW                      = STOP
current-state anchor promotion      = NO
jerk-response promotion             = NO
interaction-response branch status  = CLOSED
boundary transport                  = remain OFF
relative ranker                     = remain frozen
```

## 3. 为什么失败：不是“参数不够”

V48.73 试图回答：

> 从当前 acceleration 出发，history-supported extreme 以 observation-derived jerk 传播后，外部 agent 对该 recovery 的 future occupancy 是否可信？

但实验显示这类 exogenous-response plausibility 并未与两个真正需要的判别轴对齐：

1. **factual deployability:** teacher-feasible 应比 teacher-infeasible 保留更多支持；
2. **intervention safety:** safe-positive 应比 harmful witness 保留更多支持。

N73 与 O73 各自偶尔改善不同轴，却没有任何 cell 同时改善两轴。这说明问题不是一个 response-rate 常数、history window 或 gain 没调好，而是当前 scalar external-trust question 本身与最终 absolute feasibility predicate 不同构。

它仍在问“外部 motion set 有多可信”，却没有直接问：

> 这条已经 actuator-projected、candidate×option 对齐的 recovery，是否以足够快的 signed-clearance 进展保持安全或偿还 contact penetration？

因此继续增加 acceleration/jerk envelope 复杂度会增加自由度和论文叙事负担，却缺少正证据。

## 6. 三个 regime 的解释

### Safe

Safe 已接近稳定是合理工作判断，但在 source 尚未 GO 前不应写成正式 deployment claim。V48.74 对远离边界且不快速闭合的 recovery 给出近 1 的 factor，且没有 regime ID，因此设计目标是 non-interference，而不是为 Safe 单独训练 expert。

### Near-Contact

主要问题不是是否检测到“距离小”，而是能否区分：

- 接近边界但 projected recovery 正在建立 separation；
- 当前尚未 contact，但 closing trend 已无法在剩余 recovery 时间内逆转。

静态 clearance/hull 会把这两种情况混在一起。V48.74 用 `h`, `h_dot` 和剩余 recovery time 直接表达 deadline-aware viability。

### Contact

Contact 的核心是偿还 penetration debt，而不是仅预测一个更复杂的 agent acceleration envelope。对 `h<0`，finite-time barrier 自动要求正向 separation progress；若 projected recovery 的 outward speed/acceleration 不足，debt 为正。该机制与 Safe/Near 使用同一公式，不是 Contact-conditioned policy。

## 7. V48.74 OC-SVBW

### 7.1 定义

对 actuator-projected recovery `x_e(t)` 和 observation-only agent continuation `x_j(t)`，定义 signed clearance：

```text
h_j(t) = ||x_j(t) - x_e(t)|| - (r_e + r_j)
```

`h>0` 为安全分离，`h=0` 为 contact boundary，`h<0` 为 penetration。令：

```text
tau(t) = max(T_recovery - t, delta_t)
```

一阶 finite-time barrier：

```text
beta_1(t) = h_dot(t) + h(t) / tau(t)
B_1(t)    = tau(t) beta_1(t)
          = h(t) + tau(t) h_dot(t)
```

二阶 high-order barrier：

```text
beta_2(t) = h_ddot(t)
            + 2 h_dot(t) / tau(t)
            + 2 h(t) / tau(t)^2

B_2(t)    = 0.5 tau(t)^2 beta_2(t)
          = h(t) + tau(t) h_dot(t)
            + 0.5 tau(t)^2 h_ddot(t)
```

若 `h<0`，`beta_1>=0` 要求 penetration 以足够速率在 deadline 前收敛到 0；若 `h>0`，同一条件防止 clearance 比允许的 finite-time envelope 更快耗尽。

### 7.2 两个嵌套 arm

#### P74_FIRST_ORDER_SVBW

```text
d_1 = max_{j,t} [-B_1(j,t)]_+ / physical_length_scale
w_1 = 1 / (1 + d_1)
```

只检验 signed clearance + radial progress 是否解决双选择性。

#### Q74_MAIN_OC_SVBW

```text
d_2_raw = max_{j,t} [-B_2(j,t)]_+ / physical_length_scale
d_Q     = max(d_1, d_2_raw)
w_Q     = 1 / (1 + d_Q)
```

二阶 arm 是 non-compensatory：正 acceleration 证据不能抹去失败的一阶 finite-time condition。

### 7.3 Why this is a different branch

OC-SVBW 不再构造 acceleration-history ball、box、hull、anchor 或 jerk response set。它只使用：

- deployable observation；
- 当前 agent continuation；
- 已 actuator-projected 的 executable recovery；
- signed clearance 的 pathwise dynamics；
- option 自身已有 recovery deadline。

没有新 horizon、threshold、regime ID、expert、router 或 privileged future。

### 7.4 Schema 与隔离

```text
engineering_version = v48.74.0-OC-SVBW
schema              = 10
feature_dim         = 22
source              = signed_finite_time_viability_projected_recovery_witness
coordinate 20       = first-order signed finite-time viability debt
coordinate 21       = non-compensatory high-order viability debt
```

坐标 0–19 保持 accepted base semantics。P/Q 同时物化 20/21，只由模型选择坐标；共享一个 persistent cache。唯一 trainable state 仍应是两个 role-isolated absolute-semantic gains。

## 8. V48.74 预注册判决

1. **工程门：** runtime provenance、reference reuse、row alignment、state isolation、NaN/OOM、test-root access 全部通过。
2. **Identity：** P/base、Q/base、Q/P 的 positive-certificate sign/set 8/8 exact。
3. **P causal gate：** `P74 - accepted projection-fidelity reference` 检验一阶 finite-time viability。
4. **Q incremental gate：** `Q74 - P74` 检验 high-order acceleration term。
5. **Main ordering：** Q 相对 accepted reference 的 source AUC 和 positive-certificate probability AUC 至少 6/8 为正。
6. **Mechanism relevance：** 不再 promotion 只有 `1e-4` 且 scene-cluster interval 跨零的效应；至少应出现可复现的 `~5e-3` 级 ordering 改善，或 bootstrap lower bound 为正。
7. **Dual selectivity：** 至少 6/8 同时满足 TF>TI 和 safe-positive>harmful；harmful/TI 不得 relapse。
8. **Non-floor：** 排除 exact-0.5 rows 后至少 6/8 正向。
9. **Full source：** 8/8 正，至少 6/8 `delta AUC>=+0.01`；safe-positive 相对 P66 8/8 改善且至少 6/8 `>=+0.05`；历史 selectivity caps 保持。
10. **Safe continuity：** 不使用 regime input，且 Safe validation/calibration 的 certificate/admission 不发生统计显著退化；正式 closed-loop Safe non-interference 在 source GO 后验证。

## 10. 性能与无效计算

### 已落地

- P/Q 两个诊断在一个 vectorized pass 中计算；
- P/Q 使用相同 schema 和 canonical persistent-cache key，第二 arm 必须 cache hit；
- `np.gradient` 在 time axis 上一次完成一、二阶导数，没有 Python time loop；
- time grid、remaining-time powers 和 normalization 复用；
- historical references 只按 hash 复用，不重新训练；
- runner 默认 `PERSISTENT_TENSOR_CACHE_BUILD_WORKERS=8`，并限制 OMP/MKL thread oversubscription；
- env 未开启时 V48.73 行为保持不变；开启但找不到 time-resolved signed clearance 时 fail closed，不回退旧 N/O 坐标。

### 有意没有删除的部分

为了先保证 execution-exact attribution，V48.74 初版仍通过 V48.73 的共享 base materializer 获得 time-resolved clearance，再替换坐标 20/21。因此旧 history preprocessing 在 cold build 中可能仍支付一次，但不会为 P/Q 支付两次。

在目标数据上完成 old/new feature equivalence 与 runtime profiling 后，可以删除 dormant N/O acceleration-history/jerk calculations；在此之前贸然删除可能改变其他 0–19 feature 或缓存顺序，不值得用工程风险换取不可归因的速度数字。

## 12. 本轮最关键结论

> 从 ball、box、joint hull、current-state anchor 到 jerk-limited response，增加 observation-only external response-set 的精细度没有产生 dual-selective、non-floor-consistent、可复现的 absolute feasibility source。当前应停止外部 response enrichment，转而直接验证 actuator-projected executable recovery 的 finite-time signed viability。

V48.74 是这一新假设的最小、regime-agnostic、物理可解释因果实验；在其 GO 前，boundary transport、relative ranker 和 regime-specific mechanisms 继续冻结。
