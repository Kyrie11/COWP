# WOMD + Waymax closed-loop dataset backend

This backend is selected with:

```bash
--set data_source=womd --set simulation_backend=waymax_closed_loop
```

It intentionally fails if `waymax`/`jax` cannot be imported. It does not silently fall back to the OC-RAP surrogate backend.

## Semantics

- WOMD is read through Waymax dataloader utilities into `SimulatorState`.
- Planning time is represented by `BaseEnvironment.reset(..., init_steps=t+1)`, so `state.timestep == t` before candidate-prefix rollout.
- Candidate prefixes are executed by Waymax dynamics. The default training backend uses `InvertibleBicycleModel`; debug/replay alignment can use `StateDynamics` by overriding `waymax.prefix_dynamics=state`.
- Non-SDC agents use Waymax reference/log playback. Natural future object appearance is controlled by Waymax `allow_new_objects_after_warmup`.
- Optional hidden stress roots are generated by augmenting the Waymax reference trajectory in an unknown, drivable, not-visible-free cell; the resulting state is still rolled forward by `BaseEnvironment.step` with object injection enabled.
- Recovery labels are computed by executing each recovery controller through Waymax and reading Waymax metrics over the recovery horizon. The stored `m_star`, `r_orc_star`, `r_dep_star`, and `oracle_gap_star` therefore come from Waymax recovery rollout, not from the old surrogate teacher.

## Required diagnosis checks

For a dataset to support a Waymax closed-loop primary benchmark, `diagnose.json` should have:

```json
"supports_waymax_runtime_claim": true,
"waymax_runtime_fraction": 0.95 or higher,
"runtime_backend_counts": {"waymax_closed_loop": ...},
"supports_fra": true,
"supports_drs_labels": true,
"supports_calibration_protocol": true,
"supports_heldout_test_protocol": true
```

and no schema / hidden-spawn / split leakage failures.
