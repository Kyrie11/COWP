COWP v11-BCOT：部署、双 GPU 训练、离线 gate 与 100 场景 probe
================================================================

重要结论
--------
1. v11 复用现有 tensor_cache_*_waymax_transport_v9，不需要重建 WOMD labels、tensor cache、Waymax replay 或 transport sidecar。
2. 从 v10-GCT planner checkpoint 初始化；不要回退到 v8/v9。
3. 训练阶段按依赖关系串行，但每个阶段使用 GPU0+GPU1 DDP。
4. learned-offline 主评估与 pairmax ablation 分别占 GPU0/GPU1 并行。
5. gate 通过后：第一波 COWP-BCOT(GPU0)+conventional(GPU1)；第二波 pairmax(GPU0)+Pareto ablation(GPU1)。
6. 100 场景仅用于机制 smoke test，不用于 SOTA 声明。

- FallbackRate

开发 gate：
- WitnessQuality/AUPRC >= 0.60
- BCOT/FalseSafe_AUPRC >= 0.65
- LearnedAcceptNCFRecall >= 0.30
- LearnedAcceptedCandidateRate >= 0.10
- FallbackRate <= 0.25
- conventional - COWP SelectedFalseSafeRate >= 0.08

未通过时脚本会停在 Waymax 前。不要手动放松 gate；将上述 JSON 和两个 history 文件重新打包分析。

- 相对 pairmax：fallback 和可行候选保留明显改善；
- 相对 Pareto ablation：核心 safety/option 指标不退化。

八、不要执行
------------
- 不要重建 WOMD labels/tensor cache/Waymax replay/transport_v9。
- 不要用 v8 checkpoint 替代 v10 初始化。
- 不要把附着的稀疏 candidate outcome 当作在线闭环结果。
- 不要因为 gate 失败而降低 NCF recall、accepted rate 或 fallback 门槛。
- 不要跳过 pairmax ablation；它是证明 v11 聚合创新有效的关键证据。
- 不要直接跑 5000 场景或多种子，先通过 100/1000 场景开发检查。
