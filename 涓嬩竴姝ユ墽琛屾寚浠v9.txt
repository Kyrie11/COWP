三、第一阶段：并行增广 cache + 双卡 transport/planner 训练 + offline gate + 100 场景 probe
---------------------------------------------------------------------------------------
说明：
- train/val transport label augmentation 会在 CPU 上并行执行；
- transport 和 planner 各自使用 GPU 0/1 DDP；
- Waymax probe 中 COWP 与 conventional 分别使用一张 GPU 并行；
- INIT_CKPT 必须指向实际 v8 best planner checkpoint；
- offline gate 默认不使用 outcome-risk penalty，以隔离核心机制；
- online 默认只使用较小 collision/offroad risk penalty 0.75；log-divergence 始终关闭。

PYTHON_BIN=/home/senzeyu2/miniconda3/envs/mfrp/bin/python \
TORCHRUN_BIN=/home/senzeyu2/miniconda3/envs/mfrp/bin/torchrun \

五、offline gate 通过标准
-------------------------
脚本会自动要求：
- threshold selection points >= 3
- Witness AUPRC >= 0.50
- LearnedAcceptNCFRecall >= 0.25
- LearnedAcceptedCandidateRate >= 0.08
- FallbackRate <= 0.30
- SelectedFalseSafeRate 相比 conventional 至少下降 0.03

gate 不通过时脚本会在 Waymax probe 前退出。

十一、若 v9 gate 仍不通过
------------------------
按顺序处理：
1. 确认 transport diagnostics 中 mode_conflict/mode_retain/root assignment 覆盖合理；
2. 查看逐 mode/root loss 是否下降；
3. 统计 conflict/retain 正负样本比例，不要先调 selector；
4. 若 root matching 噪声大，将 hard nearest-ADE 改为 soft OT/Sinkhorn matching；
5. 若 natural mode recall 不足，先强化 natural decoder，而不是放松 witness；
6. 若 offline 通过而 online 失败，再做 Waymax hard-negative mining；
7. 不要绕过 gate 直接跑 5000 场景。

十二、实验协议的重要限制
------------------------
当前 real Waymax evaluator 只控制 SDC，configs/eval_cowp_v9.yaml 已明确标记实际 non-ego protocol 为 logged replay。
论文中“logged/rule/learned reactive mixture”目前没有被 04_eval_closed_loop 实现。
投稿前必须二选一：
- 实现并验证 reactive non-ego mixture；
- 或修改论文实验描述，使用诚实的 log-replay closed-loop + 独立 counterfactual stress/human audit。
